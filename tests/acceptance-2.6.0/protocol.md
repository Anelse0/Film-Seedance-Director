# 2.6.0 开发与验收协议

授权：用户要求严格依《Film-Director 2.5.5：工作流与编剧能力评估》按 P0–P3 开发、逐步提交并推送。基线 v2.5.5 / e05da76。开发环境为独立克隆，安装副本在完整验证后同步。

1. P0：唯一执行契约，终点与排除项，保存与确认分离，结构化路由校验，三种单元分离；工程独立验收后提交推送。
2. P1：当前/确认/探索版本，旧稿快照，下游失效与恢复，稳定资产 ID，Git 或归档基线；工程独立验收后提交推送。
3. P2：有问题才试写比较与回流，跨场与跨集发展，信息顺序试验，正文优先与连读，核实来源；提交推送候选版本，不预告创作提升。
4. P3：旧版／只清理流程／完整方法三配置，同模型和相近总预算，完整任务、失败与退步证据、匿名用户选择。生成与模型审阅不代替用户偏好；用户尚未评审时明确 pending，不记胜率或通过。

保护：保持现有 Prompt 编译、生产预检、原始情绪库、表演描述、强度/克制机制与 C→D 保真。原 27 项保护清单中仅 templates/asset-registry.md 按用户批准的 P1 修正稳定资产 ID；该模板不属于 Prompt 编译或情绪描述，例外单独记录，其余 26 项哈希保持不变。不得以修改预期哈希掩盖核心变化。

预先定义的质量目标：约束违规为零；新方法须在实际作品的选择、发展、对白或结尾上有可指出的收益，同时记录缺点；盲选允许平局与都不好；小样本不宣称统计显著性。先单独读正文，不靠分析说明补剧情。首次产出与同等修订机会后的作品分开评价。若无法区分改善来自流程清理还是新方法，结论明确不确定。新题留出复验，禁止挑选成功输出。
